The operating principle

A backup is a promise.
A tested restore is evidence.

This project turns an existing EBS backup pattern into a reusable, reviewable recovery scaffold: define the objective, restore separately, validate the workload, and measure the outcome.

Scaffolded—not deployedNo successful restore drill is claimed until real evidence is recorded.
01 / Protect

Known recovery points

Encrypted AWS Backup storage with explicit scheduling and retention.

02 / Exercise

Isolated restoration

A new test resource is restored without replacing or mounting over the source.

03 / Prove

Measured outcomes

RTO and RPO pass only when workload validation also succeeds.

Recovery model

Two objectives.
One complete test.

Timing begins with declared events, not estimates after the fact. The scorecard uses timezone-aware timestamps and rejects a recovery sequence that is missing or out of order.

RTO120 minutes

How long the workload may remain unavailable—from incident declaration through completed validation.

Reference default / replace through reviewed input
RPO1440 minutes

How old the selected recovery point may be when measured from the declared incident.

Reference default / replace through reviewed input

Evidence path

From volume to verdict.

  1. 01

    Protected volume

    The exact approved EBS ARN enters the backup plan.

  2. 02

    Encrypted vault

    Recovery points use an existing customer-managed KMS key.

  3. 03

    Separate restore

    A scheduled test creates an isolated EBS resource.

  4. 04

    Workload validation

    Local integrity and usability checks decide whether the restore works.

  5. 05

    Sanitized scorecard

    Observed objectives and a protected evidence reference record the result.
